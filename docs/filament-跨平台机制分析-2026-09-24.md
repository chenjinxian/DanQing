> 2026-09-24 战略分析（Authored：源码取证报告，非参考移植）。姊妹篇：
> `itwinjs-core-WASM可替换性分析-2026-09-24.md`、`filament-PBR材质接入分析-2026-09-24.md`、
> `filament优秀实践移植分析-2026-09-24.md`、`itwinjs-tile-vertexLUT机制深挖-2026-09-24.md`。
> 综合架构结论见 `双源优势结合-目标架构与重构路线-2026-09-24.md`。

## 1. 结论摘要

1. filament 的跨平台能力建立在**一条 Driver 抽象缝**之上：`DriverAPI.inc` 用宏 X-machina 一次生成 144 个 API 的"录制 + 派发 + 虚函数"三份代码（99 异步 + 45 同步），四个后端（OpenGL/Vulkan/Metal/WebGPU）+ noop 全部实现同一表面。
2. 着色器是**离线多路编译 + 运行时按语言选块**：matc 为每个 TargetApi（OPENGL/VULKAN/METAL/**WEBGPU**）生成 GLSL→glslang→SPIR-V→spirv-cross（MSL/ESSL）或 **tint（WGSL）**，全部以 filaflat chunk（MAT_GLSL/MAT_SPIR/MAT_WGSL…）存入一个 `.filamat` 包；运行时 `MaterialParser::shaderLanguageToTags` 按后端首选语言取块。
3. **WebGL2 路径极薄**：`PlatformWebGL.cpp` 仅 60 行——swapchain 创建是透传、makeCurrent/commit 是 no-op（浏览器合成）；WebGL 上下文甚至不是 C++ 创建，而是 JS `canvas.getContext("webgl2")` + `GL.registerContext`。
4. **WebGPU 后端已实质成型（62 文件/13.1k 行）但官方定位实验性**：默认 OFF（`build.sh:204`）、README 不列 WASM、依赖 **Dawn**（third_party 578MB，非 wgpu-native）；WASM 上不经 native Dawn 而走 **emdawnwebgpu port**（两步构建）。
5. DanQing 的 Driver 表面已覆盖 filament 几乎全部 144 条目（161 个 virtual，含 itwinjs 驱动的扩展），**缺的不是 API 面而是三条接缝**：Emscripten 平台分支、GLSL 300 es 目标、能力协商层（getFeatureLevel/getShaderLanguages）。
6. DanQing 上 WebGL2（WASM）是**小工程**（参照 filament：平台层 60 行 + 着色器版本目标 + 少量 ES 差异适配）；WebGPU 是**大工程**（参照 filament：13k 行后端 + Dawn 578MB），且真正的难点在 **WGSL 生成**——DanQing 的运行时 GLSL 字符串体系与 filament 的离线 matc 体系结构性不同。
7. 最大风险不是代码量而是**工具链体量与生成链冲击**：Dawn/tint 引入、itwinjs 着色器字符串→WGSL 的翻译质量、Emscripten 单线程与 4GB 内存边界。

## 2. filament 跨平台机制四层拆解

### 2.1 后端抽象缝（Backend Seam）

**API 面的形态——宏生成的单一事实源。** 后端接口不是手写的虚函数列表，而是一个无 include guard 的 `.inc` 文件 `filament/backend/include/private/backend/DriverAPI.inc`（全文 753 行），用三种宏声明全部 API：

- `DECL_DRIVER_API`（异步、入队执行）/`DECL_DRIVER_API_RETURN`（异步、返回 Handle）/`DECL_DRIVER_API_SYNCHRONOUS`（同步、可立即返回）——声明机制见 DriverAPI.inc:42-134（`APPLY_N`/`PAIR_ARGS_N` 变参展开技巧）。
- **条目统计**（全文逐条计数）：**99 个异步 API + 45 个同步 API = 144 条**。其中 handle 创建的 TAGGED_R_N 共 **30 个**（createVertexBufferInfo/VertexBuffer/IndexBuffer/BufferObject/Texture ×4 种 View 变体/ExternalImage ×3/importTexture ×2/RenderPrimitive/Program/DefaultRenderTarget/RenderTarget/Fence/Sync/SwapChain/SwapChainHeadless/TimerQuery/DescriptorSetLayout/DescriptorSet/mapBuffer，DriverAPI.inc:183-364），destroy/unmap 共 16 个（:371-386）。
- 一个后端必须实现的完整表面（分组）：
  - 帧生命周期：tick/beginFrame/endFrame/flush/finish/resetState（:144-176）
  - 资源创建/销毁/更新：30 create + 16 destroy + setVertexBufferObject/updateIndexBuffer/updateBufferObject(±Async ±Unsynchronized)/update3DImage(±Async)/generateMipmaps（:183-558）
  - 渲染状态：beginRenderPass/endRenderPass/nextSubpass/bindPipeline/bindRenderPrimitive/bindDescriptorSet/setPushConstant（:565-583, :555）
  - Swapchain：makeCurrent/commit/setFrameRate（:589-601）
  - 绘制：draw2/drawArrays/draw/dispatchCompute/scissor（:678-704）
  - 回读：readPixels/readTexture/readBufferSubData（:626-648）
  - Blit/Resolve：blitDEPRECATED/resolve/blit（:655-676）
  - **45 个同步能力查询**：isTextureFormatSupported(:405)…isDepthClampSupported(:422)、getMaxDrawBuffers(:424)、getMaxTextureSize(:426)、**getFeatureLevel(:433)**、isWorkaroundNeeded(:432) 等（:393-437）

**三处消费同一 .inc（这是该设计的核心）**：
1. `Driver.h:119-141` 区域（DriverApi 前端，把调用编码进命令流）；
2. `backend/src/CommandStreamDispatcher.h:49-72` —— `ConcreteDispatcher<ConcreteDriver>` 模板将 DriverAPI.inc include 三次（:56-71 定义三种宏再 `#include "private/backend/DriverAPI.inc"` :71），生成"从命令缓冲解码并直接调 `ConcreteDriver::method`"的函数指针表；
3. 各后端 Driver 类（如 `WebGPUDriver final : public DriverBase`，WebGPUDriver.h:64）。

即：**加一条 API = 在 .inc 加 3 行，前端录制器、派发器、全部后端编译器同时强制跟进**，漏实现即编译错误。`Driver::getDispatcher()`（Driver.h:104）在 CommandStream 初始化时取表一次。

**后端枚举与运行时选择。** `Backend : uint8_t { DEFAULT, OPENGL, VULKAN, METAL, WEBGPU, NOOP }`（`backend/include/backend/DriverEnums.h:175-182`）；`FeatureLevel { FL0=ES2, FL1=ES3.0(默认), FL2=ES3.1+16tex+cubemap arrays, FL3=+31 tex units }`（DriverEnums.h:151-156）。`PlatformFactory::create(Backend*)`（`backend/src/PlatformFactory.cpp:93-198`）按**编译期平台宏**选 Platform 类并回填 resolved backend：DEFAULT 解析规则 :105-117（EMSCRIPTEN→OPENGL :106-107、Android→OPENGL、Apple→METAL、VULKAN 可用→VULKAN、否则 OPENGL）；WEBGPU 分支 :138-156（含 `WebGPUPlatformWasm` :148-149）。`FEngine::create`（`filament/src/details/Engine.cpp:175-225`）调 PlatformFactory→`platform->createDriver(...)`（:200），多线程模式下 Driver 跑在独立渲染线程（:204）。

### 2.2 着色器跨平台管线

**这是 filament 跨平台最重的机制**，完整链路（全部证据来自 libs/filamat + libs/filaflat + filament/src）：

**① matc 前端。** `tools/matc`：`-a opengl|vulkan|metal|webgpu|all`（`tools/matc/src/matc/CommandlineConfig.cpp:332-343`）、`-p desktop|mobile|all`（:319-326）、`-f feature-level`（:129）。`TargetApi { OPENGL=0x01, VULKAN=0x02, METAL=0x04, WEBGPU=0x08, ALL }`（`libs/filamat/include/filamat/MaterialBuilder.h:78-88`）——**WEBGPU 是一等 TargetApi**。

**② 代码生成。** `MaterialBuilder::generateShaders`（`libs/filamat/src/MaterialBuilder.cpp:893`）对每个 API×ShaderModel 变体拼 chunk（`ShaderGenerator` + `shaders/src/` 下的 filament chunk 库），`CodeGenerator::generateCommonProlog`（`libs/filamat/src/shaders/CodeGenerator.cpp:48-102`）打 `#version`：mobile → `310 es`（走 SPIRV 或 FL≥2）/ `300 es`（FL1）/ `100`（FL0）；desktop → `450 core`（走 SPIRV）/ `410 core`。**注意：送 glslang 的中间 GLSL 是"SPIR-V 友好"的 ESSL310/GLSL450（Vulkan 语义）**（MaterialBuilder.h:90-104 注释）。

**③ glslang → SPIR-V。** `libs/filamat/src/sca/GLSLTools.cpp:564-621`：始终加 `EShMsgSpvRules`（:578）；VULKAN/METAL/**WEBGPU 再加 `EShMsgVulkanRules`**（:579-592）；客户端 OpenGL 用 `EShTargetOpenGL_450`（:606），Vulkan/Metal/WebGPU 用 `EShClientVulkan + EShTargetVulkan_1_1`（:611-612），SPIR-V 目标 `EShTargetSpv_1_3`（:619）。`GlslangToSpv` 调用点：`libs/filamat/src/GLSLPostProcessor.cpp:711-712`（Optimization::NONE）/:806-807（PREPROCESSOR）/:844（full）。

**④ 按后端分叉翻译**（GLSLPostProcessor.cpp，三条优化路径结构相同）：

| 后端 | 翻译器 | 证据 |
|---|---|---|
| Metal | **spirv-cross** `CompilerMSL` | `#include <spirv_msl.hpp>` :41；`spirvToMsl` :394；MSL 2.0/2.2/2.3 选项 :404-418；argument buffer 替换 :564-567 |
| OpenGL | **spirv-cross** `CompilerGLSL` | `#include <spirv_glsl.hpp>` :40；`CompilerGLSL` :913；输出版本 mobile {100,300,310} es / desktop {410,430}（`GLSLTools.cpp:548-562`，消费于 :882-885）——即 **ESSL 300 是 SPIR-V 反翻译出来的**，不是直接生成 |
| Vulkan | 无翻译 | SPIRV-Tools 优化（`createOptimizer` :997 / `registerPerformancePasses` :1082），SPIR-V 原样入包 :846-861 |
| **WebGPU** | **tint** `::tint::SpirvToWgsl` | `#include <tint/tint.h>` :43（FILAMENT_SUPPORTS_WEBGPU 门控 :42）；`spirvToWgsl` :572-624；调用 :599；**WGSL 专属修补**：`CreateSplitCombinedImageSamplerPass` :576 + `rebindImageSamplerForWGSL` :580（:284-330）——GLSL 的 combined sampler 必须拆成 texture+sampler 并重绑 |

**⑤ 打包。** 单包多后端块：`MaterialChunkType.h:44-49` —— `MaterialGlsl="MAT_GLSL"`/`MaterialEssl1="MAT_ESS1"`/`MaterialSpirv="MAT_SPIR"`/`MaterialMetal="MAT_METL"`/`MaterialWgsl="MAT_WGSL"`/`MaterialMetalLibrary="MAT_MLIB"`；字典块 `DictionaryText/Spirv/MetalLibrary`（:99-101）；材质要求 FL 存 `MAT_FEAT` chunk。写入：`MaterialBuilder.cpp:1192-1224`（WGSL 块 :1222-1223）。zstd 压缩 + CRC32 后 flatten（`build()` :1297/:1433）。

**⑥ 运行时选块。** 每后端 Driver 报首选语言列表：`OpenGLDriver::getShaderLanguages` 返回 `{ES2?ESSL1:ESSL3}`（`backend/src/opengl/OpenGLDriver.cpp:442-445`）；Vulkan `{SPIRV}`（VulkanDriver.cpp:370-373）；Metal `{MSL, METAL_LIBRARY}`（MetalDriver.mm:1266-1272）；**WebGPU `{WGSL}`**（WebGPUDriver.cpp:147-150）。`FEngine::getShaderLanguage()`（details/Engine.h:310-327）→ `MaterialParser` 构造时收列表（`filament/src/MaterialParser.h:57`），`chooseLanguage` 取**第一个包内存在的语言**（MaterialParser.cpp:163-176，缺则 `ERROR_MISSING_BACKEND`），`shaderLanguageToTags`（:62-79）把语言映射到 chunk 对——**WGSL→{MAT_WGSL, DIC_TEXT} 纯文本路径**。filaflat `MaterialChunk::getShader`（`libs/filaflat/src/MaterialChunk.cpp:322-334`）按块类型走 text/binary 两条解码。`MaterialDefinition.cpp:803-830` 取回 VS/FS 组装 `Program` 并 `.shaderLanguage()`。

**WebGL(ESSL 300) 与 WebGPU(WGSL) 的生成路径差异一句话**：ESSL300 = glslang→SPIR-V→**spirv-cross 反译回文本**（因 OpenGL 后端运行时就是 glShaderSource 文本）；WGSL = glslang→SPIR-V→**tint 翻译**（WebGPU 后端运行时只收 WGSL 文本——`WebGPUProgram.cpp:81-87` 构建 `wgpu::ShaderSourceWGSL`，全后端无 `ShaderModuleSPIRVDescriptor`，specialization constant 在模块创建前烘进 WGSL `override` 默认值，WebGPUProgram.cpp:73-80 + `utils/SpecializationConstantProcessor.cpp:40-79`）。

### 2.3 平台层 vs 后端层

**职责边界（filament 的精确划分）**：

- **Platform（`backend/include/backend/Platform.h`）**：OS 资源与上下文工厂。核心 `createDriver(void* sharedContext, DriverConfig)`（:413，"backend API 初始化延迟到 createDriver"注释 :90-92）；另含帧率查询/设置（:489/:500）、compositor timing（:436/:448）等显示管线协商。Platform 的 `terminate()`/`pumpEvents()`（:423）也在此层。
- **OpenGLPlatform（`backend/include/backend/platforms/OpenGLPlatform.h`）**：GL 系的平台缝——`createSwapChain(void* nativeWindow, flags)`（:127）与 `createSwapChain(w,h,flags)` headless 变体（:141）、`destroySwapChain`（:148）、`makeCurrent(ContextType, draw, read)`（:222/:240）、`getDefaultFramebufferObject`（:176）、`beginFrame/endFrame/preCommit`（:184/:193/:250）。**Driver 侧接线**：`OpenGLDriver::createSwapChainR` 直接转调 `mPlatform.createSwapChain(nativeWindow, flags)`（`backend/src/opengl/OpenGLDriver.cpp:2203-2208`）；`commit` → `mPlatform.commit`（:3175-3179）。
- **Driver 后端**：只面对 GPU API 对象（Program/Texture/Buffer/RT 的创建与绘制），**不碰窗口句柄语义**——swapchain 对 Driver 而言是不透明 `void*`（OpenGLPlatform.h:127 返回 `SwapChain*`，各平台自定义结构）。WGL 平台 312 行、EGL/Cocoa 各 300-600 行，全部是"上下文 + 表面 + present"三件事。
- **WebGPU 同构**：`WebGPUPlatform.h:65-87` 六个虚函数——`getSurfaceExtent`/`createSurface`/`requestAdapter`/`requestDevice`/`getConfiguration`/`getAdapterOptions`，全部 Dawn wgpu 类型；Driver（WebGPUDriver.cpp）不创建 surface/device，只用 platform 交付的 `wgpu::Device`。

**SwapChain 抽象的跨平台差异**：desktop GL（WGL/EGL/Cocoa）= 原生 surface + 显式 `commit`(SwapBuffers)；**WebGL = 空实现**（见 §3.1）；Vulkan = Platform 子类管 VkSurfaceKHR + swapchain 重建；WebGPU = wgpu::Surface + `Present()`（WASM 上 Present 也省掉，见 §3.2）。

### 2.4 能力协商

三层机制：

1. **细粒度 bool 查询**——45 个同步 API（DriverAPI.inc:393-437），材质系统按需调用（如 isTextureFormatFilterable 决定纹理降级）。
2. **FeatureLevel 分级**——Driver 运行时解析：GL 系 `OpenGLContext::resolveFeatureLevel`（`backend/src/opengl/OpenGLContext.cpp:565-633`）：ES2→FL0、ES3.0→FL1、ES3.1+`EXT_texture_cube_map_array`→FL2、片元/顶点采样器数达标→FL3（:587-593）、desktop GL4.3+→FL2/3（:613-624）、bug 可强制 FL0（:628-630）。WebGPU 从 `mDeviceLimits.maxSamplersPerShaderStage` 映射（WebGPUDriver.cpp:983-1002）。引擎启动时钳制：`mActiveFeatureLevel = min(builder, driverApi.getFeatureLevel())`（details/Engine.cpp:380），运行日志 :382-383；运行时只升不降（`setActiveFeatureLevel` :1699-1704）。
3. **材质声明要求 FL**——`MAT_FEAT` chunk + `FMaterial::getFeatureLevel`（details/Material.h:154），matc `-f` 选择生成哪档变体（FL0 抑制 skinning/stereo，`ShaderGenerator.cpp:888-903`）。

## 3. WebGL 与 WebGPU 路径专项

### 3.1 WebGL / Emscripten 路径

**构建**：无自定义工具链文件，直接用 `${EMSDK}/upstream/emscripten/cmake/Modules/Platform/Emscripten.cmake` + `-DWASM=1`（`build.sh:446-449`）；`WASM` 为真时根 CMakeLists 只加 `web/filament-js` 与 `web/examples`（`CMakeLists.txt:995-998`）；**filamat 默认不编**（`FILAMENT_BUILD_FILAMAT` WASM 默认 OFF，`CMakeLists.txt:632-638`）——**Web 材质全部 AOT**。emcc 链接 flag（`web/filament-js/CMakeLists.txt:31-40`）：`--bind`、`ALLOW_MEMORY_GROWTH=1`、`MODULARIZE=1`、`USE_WEBGL2=1`、**`FULL_ES3`**、`MIN_WEBGL_VERSION=2`/`MAX_WEBGL_VERSION=2`——**Web 只有 WebGL2 一个 GL 目标**。WASM 上 Vulkan OFF（`CMakeLists.txt:609-610`）、Metal OFF（:627-631）。

**上下文创建（反直觉但关键）**：`emscripten_webgl_create_context` 在整树**零调用**。JS 侧 `canvas.getContext("webgl2", glOptions)`（`web/filament-js/extensions.js:107-127`，默认 majorVersion:2/antialias:false/alpha:false），C++ 绑定用 `EM_ASM` 执行 `GL.registerContext(context, options)` + `GL.makeContextCurrent(handle)`（`web/filament-js/jsbindings.cpp:481-492`），每帧 execute 前再 makeContextCurrent（:525-531）。

**平台层薄到接近不存在**：`backend/src/opengl/platforms/PlatformWebGL.cpp` 全文 60 行——`createDriver`（:26-29）；`createSwapChain` **直接返回 nativeWindow 指针当 SwapChain***（:38-41）；`makeCurrent` no-op 返回 true（:52-55，Emscripten GL 库自持当前上下文）；`commit` **no-op**（:57-58，控制权交还事件循环后浏览器自动合成 backbuffer）。OpenGLDriver 主体对 WebGL 零感知。

**GL 头与符号**：WASM 不用 bluegl（`backend/CMakeLists.txt:459-460`），`gl_headers.h:40-48` 直接 `#include <GLES3/gl3.h>`（EMSCRIPTEN 分支，禁用 gl31）；`:302-306` 手写 extern WebGL 独有的 `glGetBufferSubData`；`:330-334` 编译期禁止 EMSCRIPTEN+GLES3.1 头组合；`:322-323` 定义 `BACKEND_OPENGL_VERSION_GLES` 驱动后端条件编译。

**__EMSCRIPTEN__ 行为分叉清单**（渲染语义相关）：`OpenGLDriver.cpp:95-99` `HAS_MAPBUFFERS 0`；`:4260-4266` 回读走 `glGetBufferSubData` 而非 `glMapBufferRange`；`:2877-2886` `isTextureSwizzleSupported` 恒 false（WebGL 无 TEXTURE_SWIZZLE_x）；`CircularBuffer.cpp:27-33` 无 mmap；`filament/src/details/Texture.cpp:299-301` "WebGL does not support texture swizzling" 前置断言；`Engine.cpp:518-522` WASM 专属公开 API `resetBackendState()`。

**成熟度**：最高。README 明列 "WebGL 2.0 for all browsers supporting it"（README.md:92）；web 示例材料用 `-a opengl -p mobile`（`web/examples/CMakeLists.txt:16`）；甚至有 FL0 示例 `web/examples/cube_fl0.html`。

### 3.2 WebGPU 路径

**依赖：Dawn（含 tint），不是 wgpu-native。** `third_party/dawn` 是完整 vendor 副本（工作树 578MB，`src/tint`、`emdawnwebgpu` 均在）。native（Linux/Windows/macOS/Android）链接 `webgpu_dawn + dawncpp_headers`（`backend/CMakeLists.txt:469-471`，仅 `NOT WASM`；根 `CMakeLists.txt:986-988` Dawn 子目录同样 NOT WASM）；filamat 链 `libtint`（`libs/filamat/CMakeLists.txt:91-93`），`TINT_BUILD_SPV_READER=ON`（`third_party/dawn/tnt/CMakeLists.txt:30-32`）——tint 的 SPIR-V 读端是 WGSL 生成链的必需件；filament 对 Dawn 打了 4 个 patch（`third_party/dawn/tnt/*.patch`）。

**完成度判定**：实质成型、官方定位实验性。证据：规模 62 文件/13,146 行（Driver/Program/Texture/Buffer/SwapChain/RenderTarget/DescriptorSet/PipelineCache/PipelineLayoutCache/Blitter/MSAA resolver/Mipmap 生成器/QueueManager/StagePool 全套）；Driver 的 144 面全部实现且 getFeatureLevel 有真实逻辑（WebGPUDriver.cpp:983-1002）；有独立测试（`backend/test/test_WebGPUAsyncTaskCounter.cpp`、`test_WebGPUComposeSwizzle.cpp`、`test_WebGPUSpecializationConstantProcessor.cpp`）。但：`WEBGPU_OPTION` 默认 OFF、需 `build.sh -W` 显式开（`build.sh:204`、:1081-1085）；README 后端列表只写 "WebGPU for Android, Linux, macOS, and Windows"（README.md:91）——**WASM WebGPU 在树内可用但未广告**；`WebGPUPipelineLayoutCache.cpp:104` 还在适配 `chromium-experimental-immediate-data` 扩展。

**WASM WebGPU 形态（两步构建）**：先 `emcmake cmake ../../third_party/dawn` 构建 `emdawnwebgpu_pkg` 目标（`build.sh:387-414`），产出的 `emdawnwebgpu.port.py` 经 `--use-port=` 注入（`build.sh:428-435`）。运行时链路：JS `navigator.gpu.requestAdapter/requestDevice`（`web/filament-js/utilities.js:27-76`）→ `Filament.preinitializedWebGPUDevice`（utilities.js:75）→ Emscripten 模块配置（`wasmloader.js:70-72`）→ C++ `emscripten_webgpu_get_device()`（`backend/src/webgpu/platform/WebGPUPlatformWasm.cpp:27,51-59`）；surface 用 `wgpu::EmscriptenSurfaceSourceCanvasHTMLSelector` 链式描述子（:83-98）；**present 隐式**——`WebGPUSwapChain::present` 在 EMSCRIPTEN 下跳过 `mSurface.Present()`（WebGPUSwapChain.cpp:391-397）；`WebGPUDriver::tick` WASM no-op（WebGPUDriver.cpp:160-165）；`WebGPUWasmPolyfill.h` 补 emdawnwebgpu 缺的 `Extent2D/Origin2D/DawnTogglesDescriptor` 等类型。

**着色器约束**：WebGPU 后端**只收 WGSL 文本**（WebGPUProgram.cpp:81-87），SPIR-V 直传路径不存在——WGSL 必须由 tint 离线（matc）或在线（自携 tint）生成。

### 4.3 支持 WebGPU 的工作清单（按依赖排序）

**前置决策——WGSL 从哪来（最大的岔路口）**。DanQing 当前是运行时 GLSL 字符串组合（ShaderBuilder 拼 itwinjs 语义 GLSL），与 filament 的离线 matc 体系结构不同，三条路线：

- **A. 运行时翻译**（glslang+tint 编进 WASM 模块）：ShaderBuilder 产 GLSL 300 es → glslang（`EShMsgSpvRules`，filament 对 OPENGL 路径同款，GLSLTools.cpp:578）→ SPIR-V → tint `SpirvToWgsl` → WebGPUProgram 收文本（WebGPUProgram.cpp:81-87 只收 WGSL，此路径天然吻合）。代价：glslang+tint 进 wasm（体积 +数 MB、编译时间显著）、着色器编译延迟从 ms 级涨到百 ms 级（可缓存）。
- **B. AOT 变体枚举**（matc 式离线）：MultiVariantTechnique 变体空间有限 → 离线为每变体产 WGSL blob 随包分发。最贴 filament 正统，但要求 DanQing 把"运行时拼串"改成"枚举全部变体"，与 itwinjs ShaderBuilder 的组合语义有张力（itwinjs 参考就是运行时组合）。
- **C. 双后端源码**（WebGPU 版 ShaderBuilder 直接产 WGSL）：违反 §7 禁自创 + itwinjs 无 WGSL 参考，**不可行**。
- 建议：**A 为主**（保 itwinjs 运行时组合语义，第三方库替换属 §8.3 批准通道的同类先例），并把 tint 翻译输出接入现有 DANQING_SHADER_DUMP 体系做金样对比。

## 5. 风险

1. **Dawn 依赖体量**：578MB 源码进仓（DanQing 现 third_party 只有 stb/cgltf/googletest/Qt 级别）；构建系统侵入深（filament 需 4 个 patch + 十几条 DAWN_* cache 变量，third_party/dawn/tnt/CMakeLists.txt）；编译时间长（Dawn native 全量在 CI 上是分钟-十分钟级）；WASM 还需 emdawnwebgpu 先打包的两步构建（build.sh:387-435）。缓解：第一阶段只编 tint（WGSL 生成）不编 Dawn native，桌面 WebGPU 后置。
2. **WGSL 生成对 itwinjs 着色器字符串体系的冲击**：DanQing 的 GLSL 是"最终语义 GLSL"（410 core），不是 filament 精心构造的"SPIR-V 友好中间 GLSL"（Vulkan 语义、ESSL310/GLSL450 中间层，MaterialBuilder.h:90-104）。glslang 能吃 300 es 出 SPIR-V，但 SPIR-V→WGSL 后 combined sampler 拆分、绑定重编、MRT 语义都要修（filament 自己也要 SplitCombinedImageSampler + rebind 两道修补，GLSLPostProcessor.cpp:284-330）——**翻译质量没有 itwinjs 参考兜底，属 §5(f) Authored territory，必须配金样像素回归**；现有 DANQING_SHADER_DUMP/UV_DEBUG/MVP_TRACE 探针体系（CLAUDE.md §13.1）需要 WGSL 级等价物重建。
3. **Emscripten 性能边界**：单线程（-pthread 需 SharedArrayBuffer + COOP/COEP 跨源隔离头，且 Emscripten 线程-Web Worker 桥接要自编排；好在 DanQing 渲染栈本就零 std::thread）；WASM32 4GB 线性内存上限（大体量 tile 场景内存预算要重排）；GL/WebGPU 调用经 JS glue（library_gl.js / library_webgpu.js）有可观常数开销，高频小调用（per-draw uniform 上传——DanQing UniformHandle 每 set 即 glUniform，TD-15 修复后如此）在 WebGL2 下会比 desktop 更敏感；FULL_ES3 的 ES3 全 API 模拟非零成本；readPixels 同步回读阻塞主线程（像素级回归在浏览器里跑会放大此成本）。
4. **WebGPU 后端自身的 ground truth 弱**：filament WebGPU 仍是 opt-in 实验（默认 OFF、README 不列 WASM、专属测试仅 3 个文件），DanQing 若移植，行为兼容的权威应取 **DriverAPI 契约 + Dawn/wgpu 规范**，而非逐行照搬 webgpu 后端实现细节（否则会把实验性实现的不稳定性一并进口）。§0 来源铁律下这属于"参考未覆盖"的登记区。
5. **主线回归基础设施搬迁**：DtaTest 真窗口 harness 在浏览器环境不可用，像素级回归需重建于 headless Chrome CDP（DanQing §12.10 已有 CDP 取证经验可复用，但"合成驱动建立的视口 renderTarget:none"之坑已在案），且浏览器下 stderr 不落盘，DANQING_* 探针需改走文件旁路（现有 C:/Windows/Temp 旁路模式可迁移）。
