# 大规模模型数据：加载与渲染性能指南 + 下载运行验证配方

> 本文是 DanQing 示例程序（DisplayTestApp）处理大体量 BIM 模型数据的性能说明与
> 端到端验证手册。所有数字均来自仓内可复核的实测记录（像素级回归 harness +
> `DANQING_OPEN_TRACE` / `DANQING_TILE_TIME` / `DANQING_UI_TRACE` 诊断开关 +
> Release 真实 app 冒烟），不含推算值。测试门禁基线：**2,956 项自动化测试**。
>
> 配套数据仓：**github.com/chenjinxian/DanQing-Data**（release zip + git 双通道）。

## 2. 加载管线：为什么大体量数据依然流畅

DanQing 只做"请求获取之后"的部分（零网络约束，§8.2）——数据经 `ITileFetcher` DI
缝隙以字节进入引擎。快不是单点优化，是五段管线的合成：

### 2.1 打开链（点击卡片到首帧）

1. **manifest 单次解析共享**：打开链 props 与 fetcher 共享一份 manifest 解析 +
   哈希索引（曾双解析 58MB manifest，Debug 18.7s → **2.87s**，后续 Release
   0.4-2.0s）。
2. **重活全部下放 worker 线程**（itwinjs WorkerProxy 架构对齐）：manifest 解析、
   瓦文件读盘、imdl 二进制解析都在后台线程；主线程只做 graphics 创建（GL 上下文
   约束）。实测主线程打开阻塞 **0-2ms**。
3. **帧边界交付**：worker 完成项在帧 drain 时投递，取消/瓦销毁安全（代际丢弃 +
   weak 令牌）。

### 2.2 瓦 graphics 构建（每瓦）

| 阶段 | 修复前 | 修复后 | 手段 |
|---|---|---|---|
| 特征表 unpack（108k 特征瓦） | 1,521 ms | **19 ms**（79×） | 有序插入 O(n²) → stable_sort O(n log n) |
| Batch 逐特征更新 | 4,862 ms | O(1) 直读 | 逐特征线性 findFeature → PackedFeatureTable 行映射 O(1) |
| **单瓦 graphics 总耗时**（同瓦） | 1,635 ms | **48 ms** | 以上合计 |
| 最大采集面瓦（69MB） | — | 32.9 ms | UI 单帧内完成 |

### 2.3 流式与 LOD

- 请求面由参考同构的 SSE 选择驱动（视口像素尺寸 vs `tileScreenSize`），缩放只
  请求可见域——Bridge Edit 取景面单瓦即出首帧，深层按需下潜。
- 缺瓦走参考同款 `hasMissingTiles` 父瓦兜底：**部分数据 = 降级渲染而非失败**
  （newbridge 只下 sweep 12 卷也能完整浏览 d1-d8）。
- 多根 fallback 有序候选源（`bridge-edit` 9 根 / `newbridge` 8 根），按
  manifest 存在性条件接入。

### 2.4 交互流畅度（渲染帧率）

- 20 级连续缩放（桥模型）UI 线程最长停顿 **≤235 ms**（管线化前 10.4s）；
  缩放期峰值帧内瓦装载 122.6ms / 渲染 61.7ms——无 >0.25s 可感卡顿。
- 交互全程 FPS 用状态栏 FPS 复选框或 keyin `dta record fps` 实测；hero 动图
  （README 首屏）即连续缩放实拍。
- 大体量下渲染耗时主导项为瓦装载而非绘制：静止视口零重绘（24 步管线的
  `isRedrawNeeded` 门），相机静止不消耗 GPU。

### 2.5 正确性面（性能数字的旁证）

- Bridge Edit LOD 覆盖锁：859 请求 **0 NotFound / 0 Error**，L4 视域 691,607 px
  内容 / L8 视域 4,198,208 px。
- 每模型打开链锁：请求面 ↔ manifest 键域逐一对账 + Completed→graphics 对账 +
  像素锚（内容量 + 质心位置）。

## 4. 下载（三通道）

### 4.1 预编译包（免构建）

1. 主仓 [Releases](https://github.com/chenjinxian/DanQing/releases/tag/v0.1.0) →
   `DanQing-DisplayTestApp-v0.1.0-win64.zip`（15.9MB，含 Qt DLL + VC++ 运行库）。
2. 数据按需（下同 4.2/4.3），解压到包旁 `data\rpc-dumps\`。
3. 双击 `run.cmd`（自动设 4 个资产根环境变量后启动）。

### 4.2 release zip（按需下载，推荐起点）

数据仓 [data-v1 release](https://github.com/chenjinxian/DanQing-Data/releases/tag/data-v1)
共 38 个资产。**按模型按层选下**：

- 只想快速看效果：`instances60.zip`（135MB）或 `joeshouse.zip`（173MB）。
- 桥模型标准演示：`bridge-edit-base.zip` + `bridge-edit-sweep-part1..3of3.zip`
  （三段解压到**同一目录**叠加复原）。
- New Bridge（47.5GB）：`newbridge-v1.zip` + `newbridge-sweep-v1-part1..12of12.zip`
  即够标准浏览（6.4GB）；深层缩放再加 d9-d13（15GB 级）。**多段包必须全部解压到
  同一目录**。

### 4.3 一键脚本（sha256 校验）

源码仓根：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/data/download_dumps.ps1                      # 全部五模型
powershell -ExecutionPolicy Bypass -File scripts/data/download_dumps.ps1 -Model instances60   # 单模型
powershell -ExecutionPolicy Bypass -File scripts/data/download_dumps.ps1 -Model newbridge     # 30 包
```

自动：下载（IWR，BITS 回退）→ **sha256 逐包校验** → 解包到
`third_party/tile-sample-assets/rpc-dumps/` → 解后逐根复核。幂等（已存在跳过，
`-Force` 重下）。

### 4.4 git 直克隆（SSH 免代理）

```bash
git clone git@github.com:chenjinxian/DanQing-Data.git
set DANQING_RPC_DUMP=<克隆目录>    # 然后启动示例程序
```

目录布局与 `rpc-dumps/` 一致，免解压。差异（GitHub 100MB/文件硬门）见该仓
README：bridge-edit sweep 的 134MB 瓦与字节级 manifest 不在 git 通道。

> **中国大陆网络注记**：release 资产域（objects.githubusercontent.com）直连不稳时，
> git SSH 通道通常可用；两通道数据内容一致（除上述两处已注明差异）。

## 5. 运行

### 5.1 预编译包

`run.cmd` 启动后即见 Start 页：**8 张模型卡 + 4 张零数据示例卡**（Blank
Connection / Decoration Geometry / Cesium 陈列馆 / Analysis Style——后两张用
仓内资产，无需任何数据下载）。**Compatibility Test Seed 与 Mirukuru 两张模型卡
零数据可用**（数据随主仓/包内小族）。

### 5.2 源码构建

```bash
git clone --depth 1 https://github.com/chenjinxian/DanQing.git   # ~160MB
scripts\bootstrap_third_party.ps1                                 # Qt 6.11.1
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j --config Debug
ctest --test-dir build -C Debug --output-on-failure               # 2956 项门禁
```

工具链：VS2022 (v143) + CMake ≥ 3.20。Qt 缺席时引擎 SDK（dqBase/dqGeom/dqCommon/
dqRender，公开 API 零 Qt）仍可独立构建测试。

## 6. 验证配方（逐模型）

### 6.1 通用三步

1. **点卡片** → 状态条出现 `Opening <model>...`，完成后转
   `Opened <model> (N tile trees) — saved view rendered`。
2. **MDI 子窗标题**出现 `[ 1 ] <视图名> <viewId> (3d)`。
3. **交互验证**：滚轮缩放（LOD 逐级细化）、拖拽平移、点选（高亮）。

### 6.2 逐模型预期（首帧画面 / 打开耗时基准）

| 卡片 | 预期首帧 | 耗时基准 |
|---|---|---|
| Compatibility Test Seed | 白色六边形内容居中 | ~0.45s |
| Mirukuru | 灰色平地足印居中 | ~0.44s |
| 60 Instances (Properties) | 六色球阵 6 行×10 列 | ~0.45s |
| Joe's House | 全屋半剖视图（绿地板/灰墙/红蓝管） | ~0.57s |
| House_Model | 橙顶绿墙住宅透视斜视角 | ~0.47s |
| Baytown | iso 全厂（塔器/管线/管架） | ~0.44s |
| Bridge Edit | 全桥轮廓取景居中（1.5km） | ~2.0s |
| New Bridge | 全桥 d1 轮廓（10km，跨两屏） | 首包本地读盘秒级 |

**缺数据时**：点击模型卡 → 状态条红字
`Open <id> failed: dump package unreadable (assets root: <路径>)` + 空视口——
**不崩溃**，即提示缺哪份数据。

### 6.3 计时与诊断（可选）

| 开关/工具 | 观测面 |
|---|---|
| 状态栏 FPS 复选框 | 实时帧率 |
| keyin `dta record fps` | 帧率记录 |
| keyin `dta save image` | 当前帧 PNG 落盘 |
| env `DANQING_OPEN_TRACE=1` | `[OPEN] ... chain-done ms=` 打开链分段计时 |
| env `DANQING_TILE_TIME=1` | `[TT]` 逐瓦 fetch/parse/graphics 分段耗时 |
| env `DANQING_UI_TRACE=1` | `[UI] stall` 主线程停顿 / `[FRAME]` 帧分段 |

stderr 检查：正常会话**零 `NotFound`、零 `SEH/CRASH`**（多根候选源下域外放大
越界键的 `fetchMiss` 属预期，见各根 README）。

### 6.4 源码侧测试验证（数据回灌后）

```bash
ctest --test-dir build -C Debug -R "DumpOpenChain"          # 9 只打开链锁
ctest --test-dir build -C Debug -R "Instances60|JoesHouse"  # 单模型族
```

未下载数据时对应锁显示 **Skipped**（非失败）；回灌后转绿——
`DumpOpenChain.OpensXxx` 每锁含：树装载序钉值、saved 视图六轴钉值、请求面 ↔
manifest 键域逐一对账（零 NotFound/零 Error/零重复）、Completed→graphics 对账、
像素锚（内容量 + 质心位置）。

## 7. 故障排查

| 症状 | 原因与处置 |
|---|---|
| 模型卡点击后状态条红字 unreadable | 数据未回灌到运行配置的 assets 根——预编译包看 `run.cmd` 的 `DANQING_RPC_DUMP`；源码构建默认 `third_party/tile-sample-assets/rpc-dumps/` |
| 多段包解压后仍缺瓦（部分 LOD 粗） | 多段 zip 未解压到同一目录（条目前缀必须叠加复原）；或本身只下了浅层（深层缺瓦走父瓦兜底 = 预期降级） |
| release 下载连不上 | 中国大陆网络波动——改 git SSH 通道（§4.4）或挂代理 |
| 图标/光标异常（预编译包） | 未用 `run.cmd` 启动（资产根环境变量未设）——用 run.cmd 或手动设 4 个 `DANQING_*_ASSETS_DIR` |
| 首帧黑屏但状态条显示 Opened | 该模型 saved 视图指向空域（bridge-edit/newbridge 的坑 24 形态）——打开链已自动取景到内容域，滚轮缩放即见内容 |
