## 0. 一句话总纲

**itwinjs-core 供给"行为契约"（大体量 BIM 渲染的语义：tile 流式、多 Pass、拾取、symbology），filament 供给"机制实现"（RHI、资源管理、材质数学、跨平台）；DanQing 的最优形态 = 契约层逐字保真 + 机制层按 filament 重构内部实现。**

「最大程度重构」的安全边界：**重构内部实现形态，冻结外部行为契约**。三条红线——
1. `Viewport::renderFrame` 24 步管线步骤语义不动（CLAUDE.md §10.2）；
2. SceneCompositor 多 Pass 结构与顺序不动（§10.3：MRT 拾取/WBOIT/edge/合成 7 变体）；
3. tile 选择的行为结果不动（SSE 判定值、跳级协议、加载优先级、LRU 预算语义）。

红线之内的一切——数据表示、资源生命周期、uniform 机制、解码执行位、着色器数学、后端——都是可重构面。

## 1. 为什么这个分层是对的（五份报告的收敛结论）

| 证据 | 来源 |
|---|---|
| itwinjs 渲染栈主参考地位不可动摇：拾取 MRT/WBOIT/feature override/edge 在 filament 中**无对应物**，filament 前端整体引入会双引擎争抢 GL 上下文（§12.9 类事故） | PBR 报告 §4 方案 B 否决 |
| filament 的后处理链/命令流/glClipControl 移植会**改变像素输出或撕开已闭合伤口**——明确不移植 | 实践报告 §四 |
| DanQing 现行 imdl 消费（CPU f64 解码→fan 展开 VBO）偏离参考本体：内存 3-5×、解码阻塞；itwinjs 的 Vertex LUT（零 CPU 解码、纹理直传）才是参考机制 | LUT 报告 §4 |
| filament 的 TextureCache/FrameSkipper/UboManager 恰好在治 DanQing 的真实事故类型（resize 资源重建风暴、无背压、逐 uniform 字符串哈希）；且 `rhi::UniformBuffer`/`DescriptorSetManager` 已移植却零调用（§11.10 ported-but-uncalled 实锤） | 实践报告 §一-三 |
| filament WebGL 平台层仅 60 行且 OpenGLDriver 100% 复用——DanQing 的 filament 式 RHI 已经买好了 WASM 的船票 | 跨平台报告 §3.1/§4.2 |

## 2. 逐面最优决策表

| 方面 | 最优来源 | 决策 | 关键动作 |
|---|---|---|---|
| **大体量数据供应**（tile 选择/调度/流式） | itwinjs（filament 无对应物） | 全链补齐到参考形态 | U8 FeatureTable 链接、U9 完整选择递归+真 SSE、调度器 per-tree 优先级+swapPending+users 取消、U6 worker 解码 |
| **GPU 数据表示** | itwinjs 机制 + GL 4.1 表示升级 | 恢复 Vertex LUT 为主消费路径，再行为中性升级 | U7 LUT 主路径恢复 → U1 texelFetch、U2 RGBA16UI 8B/顶点、U3 feature 表 UBO 化、U4 真索引 |
| **每帧提交路径** | filament | UboManager 接线（消灭逐 uniform 派发）+ Culler SIMD + unsynchronized buffer 上传 | 实践报告 #3/#4/#5/#6 |
| **资源生命周期** | filament | TextureCache（resize/OIT 资源风暴）+ FrameSkipper（帧背压） | 实践报告 #1/#2（P0） |
| **材质质量** | filament（itwinjs 无 PBR） | 方案 C：管线冻结，PBR chunk 作数学库，四期路线 | PBR 报告 §5 |
| **平台覆盖** | filament | WebGL2/WASM 先行（小工程），WebGPU 远期（WGSL 运行时翻译路线 A） | 跨平台报告 §4.2/§4.3 |
| **后端完整性纪律** | filament | DriverAPI.inc 宏机制移植（加 API 编译期强制全后端跟进） | 跨平台报告 §4.4（长期） |
| **后处理** | 都不跟 | itwinjs 无 → 不做（ACES/TAA/SSAO 改变像素输出，违 §0） | 实践报告 §四 |
| **可观测性** | filament 思想 | DebugRegistry 统一运行时开关面（吸收现有 DANQING_* env 探针） | 实践报告 #6（P2） |

## 3. 重构三层分级（§0 张力管理）

### 第 1 层：行为修复（§0 强制，不是可选优化）
当前实现偏离参考机制本体的环节，"重构"在这里的含义是**归位**：
- **U8**：`ImdlTile::readContent` 产出 PackedFeatureTable → Batch → feature LUT 全链接通（拾取/按元素 symbology 的前提）
- **U7**：imdl 顶点消费恢复 LUT 纹理直传形态（顶点表不解码直接上传；polyface 路径退守 glTF/装饰图元通道）
- **U9**：完整 `selectTiles` 递归（SelectParent 协议、maxTilesToSkip/maxInitialTilesToSkip、真 `maximumSize` SSE 判定）+ 调度器对齐（per-tree loadPriority、swapPending 双缓冲、users 空取消）
- **U11**：imdl 边缘体系消费（segments/silhouettes 四级）
- 验收：参考测试移植优先（`ImdlParser.test.ts:284-443` meshopt 夹具、tile 选择测试）+ 既有像素回归全绿

### 第 2 层：行为中性优化（§11.10 等价登记制 + 每项独立像素回归锁）
- filament P0：**TextureCache**（CompositorTextures 接入）、**FrameSkipper**（Driver fence 接口已备，消费方逻辑纯新增）
- filament P1：**UboManager 接线**（ShaderProgramExecutor 绑定路径改造，SceneCompositorImpl::m_frameParams 试点）、**Culler SIMD**、**updateBufferObjectUnsynchronized**
- LUT 表示层：**U1-U4**（texelFetch/RGBA16UI/UBO feature 表/真索引）
- **U6**：解码迁移工作线程 + meshopt 解码器引入 third_party（对照 Bentley 自己的 WASM/Worker 先例）
- 每项标注 EQUIVALENCE（§11.10）：参考源、发散清单、配套回归

### 第 3 层：能力扩展（超出 itwinjs 参考的行为增量，filament 为参考源）
itwinjs 无对应行为 → 不构成"偏离参考"，而是**双源定位中 filament 一侧的兑现**：
- **PBR 材质四期**（P0 MR+方向光 → P1 IBL → P2 特性层 → P3 点光源/阴影整合），方案 C 边界：MRT/WBOIT/edge/合成全冻结，新 TechniqueId::SurfacePbr 独立注册，存量场景零税
- **WebGL2/WASM**（2-4 周评估）：PlatformEmscripten（60 行参照）+ GLSL 300 es 目标 + 能力协商层
- **WebGPU**（3-6 月评估）：WGSL 运行时翻译（glslang+tint，路线 A），Dawn 依赖裁剪策略（先 tint 后 native）

## 5. 分阶段路线（依赖排序）

| 阶段 | 内容 | 性质 | 规模评估 | 前置 |
|---|---|---|---|---|
| **0 归位** | U8 → U7 → U9 → 调度器对齐 → U11 | 行为修复（§0） | 中（tile 链路集中） | 无；立刻可启动 **M-A✅（U7+U8）M-B✅（U9+调度+TD-21）** |
| **1 机械增强** | TextureCache、FrameSkipper → UboManager 接线 → U1-U4 → U6 worker 解码 | 行为中性（§11.10 登记） | 小-中/项 | 与阶段 0 后半可并行 |
| **2 材质跃迁** | PBR P0 → P1（IBL，先修 RHI cubemap 面分发+半浮点通路两个小缺口）→ P2 → P3 | 能力扩展 | 中/期 | 阶段 0 的 LUT 主路径（纹理单元预算重排依赖） |
| **3 平台扩展** | WebGL2/WASM →（远期）WebGPU | 能力扩展 | 2-4 周 / 3-6 月 | 阶段 2 P0 之后（着色器双目标维护成本进入稳态） |
| 贯穿 | DebugRegistry 开关面、DriverAPI.inc 宏机制 | 纪律 | 小 | 任何阶段间隙 |

**为什么阶段 0 必须先于一切**：它是 §0 意义上的"完成移植"而非优化——拾取/高亮/symbology/LOD 正确性全部建立在 FeatureTable 链与选择递归之上；在偏离形态上叠加 PBR/WASM 等于把错误固化进新能力。

## 6. 明确不做（防误投清单）

- 后处理链（bloom/ACES/SSAO/SSR/TAA）——itwinjs 无，改像素即违 §0
- CommandBufferQueue 渲染线程——itwinjs 即时语义的负资产
- glClipControl 深度约定——§12.10 伤口
- filamat/matc 离线材质体系整体引入——与 ShaderBuilder 运行时组合参考决裂（WebGPU 的 WGSL 只取"运行时翻译"路线规避此冲突）
- filament 前端（FEngine/FrameGraph/Scene/View）并存——双引擎状态污染
- MDI/bindless/persistent map——GL 4.1 边界外，列为 WebGL2 远期评估项

## 7. 待决策点

1. **PBR 立项确认**：PBR 属能力扩展（itwinjs 无此行为），以 filament 为参考源兑现双源定位——是否按四期路线立项？
2. **WebGPU 立项与否与时机**：3-6 月量级 + Dawn 578MB 依赖；建议 WebGL2 落地且 PBR 稳定后再评。
3. **阶段 0/1 排期**：U8→U7→U9 归位链是否立即启动（建议：是——它是其余一切的地基）。
