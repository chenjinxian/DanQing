## 0. 范围勘察结论（参考全读记录 + DanQing 链路实证）

### 0.1 参考侧（全读）

- `core/frontend/src/common/WorkerProxy.ts`（140 行，全读）：泛型 promise-RPC——
  `createWorkerProxy<T>(scriptUrl)` 主线程代理；`WorkerInterface<T>` 每方法 →
  async；transferable 数组第二参（零拷贝移交）；msgId 关联；worker 侧
  `registerWorker` 实现注册。postMessage 语义 = 结构化克隆 + 可选 transfer。
- `core/frontend/src/internal/tile/ImdlParser.ts`（104 行，全读）：
  - `ImdlParser` 接口 { parse(options) → Promise<Document|ParseError>; release() }。
  - `acquireImdlParser(args{timeline?, noWorker?})`：
    - noWorker=true → **主线程同步 parse**（降级面原样）；
    - 无 timeline → `defaultParser` 单例（lazy 建 worker：`createWorkerProxy
      (publicPath + "scripts/parse-imdl-worker.js")`）；
    - 有 timeline → refcounted ParserWithTimeline（Dictionary 按 timeline 键）。
  - `parse(options, [options.data.buffer])` —— **transferable 零拷贝移交**。
- `core/frontend/src/internal/tile/ImdlDecoder.ts`（80 行，全读）：
  `acquireImdlDecoder`（引用计数，内持 parser）→ `decode(args{stream, system,
  isLeaf, sizeMultiplier, options, isCanceled, modelGroups...}) → Promise
  <ImdlReaderResult>`——**解析在 worker、graphics 创建在主线程**（args.system
  = RenderSystem，decode 完成后在主线程消费）= 参考的分界线。
- worker 本体 `workers/ImdlParser/Worker.ts`：registerWorker(ParseImdlWorker)，
  parse = `parseImdlDocument(bytes→Document)` 纯 CPU（JSON/LUT/量化域解析，
  零 GL）。
- 消费链：IModelTileTree 内容加载 → loader.loadGraphicsFromStream →
  decoder.decode → await → 主线程 readContent→setContent。

### 0.2 DanQing 侧（实证）

- **现行全同步**：`TileAdmin::process()`（UI 帧）→ channel dispatch →
  `tile.requestContent()` → `fetcher.fetch(url, tile, cb)`——**DumpTileFetcher
  fetch() 同步做读盘/manifest 查表**（"轮询契约"：投递只入 m_completed 队，
  下帧 `processCompleted()` 交付）→ `deliverTileContent` → readContent
  （**imdl 解析 + createImdlLutGraphics 同点执行**，含 GL）——解析与 GL 未分，
  全在 UI 线程。
- 打开链：卡片点击 → `openDumpIModel` → **DumpOpenHelper manifest 解析**
  （joeshouse 58MB，Debug 2.87s/M-I(1) 优化后实测）→ 树 props → views →
  changeView——全阻塞 UI（大包 45s 实录 M-H）。
- fetcher 界面：`ITileFetcher`（PublicAPI，Qt-free）fetch/processCompleted/
  getActiveCount/cancelAll——异步契约已有骨架（轮询交付），缺的只是**执行线程**。
- TileAdmin 已有交付缝：`deliverTileContent(tile, data)`/`reportTileFetchError`
  （通道结算 + readContent→setContent）——异步化的完成端点现成。
- 线程约束：GL 对象主线程 only（graphics 创建不可下放）；dqRender Qt-free
  （§8.2）→ 载体必须 std::thread 系（非 QThread）。

## 1. 任务分解（单道代理，逐件 RED→GREEN+提交）

**P-b1 worker 载体**（dqRender/src/tile/WorkerProxy.{h,cpp}）：
- `WorkerProxy`：持久 worker 线程 + 任务队列（std::function jobs）+ 完成队列 +
  主线程 drain 缝（`drainCompleted()`）；submit 返回句柄；单线程 worker
  （对齐参考 defaultParser 单例语义——后续扩池 TODO+锚）。
- `noWorker` 降级：submit 直通主线程执行（等价 noWorker 分支语义）。
- 锁：worker 线程 id≠主线程断言 / 完成序 FIFO / drain 前零执行（回调只在
  drain 跑——完成端主线程化的合同锁）/ noWorker 主线程直通。

**P-b2 imdl 解析分缝**（dqRender/src/tile/ImdlParser.{h,cpp} + ImdlTileTree
readContent 拆分）：
- 参考命名 1:1：`ImdlParser`{parse/release} + `acquireImdlParser(args)`；
  解析函数 = 现行 ImdlDocument 瓦字节→文档 CPU 段（自 createImdlLutGraphics
  前半拆出——**纯 CPU 零 GL**；graphics 构建半留主线程）。
- 分界线对齐参考 decode：bytes →(worker)→ Document →(main)→ graphics。
- Document 类型需可搬运（值语义/unique_ptr 移动——按现行结构定）。
- 锁：worker-parse 与 sync-parse **字节级等价**（同一瓦两路 document 对账）+
  GL 侧零调用断言（解析函数内禁 driver 触碰——静态审查+运行期线程断言）。

**P-b3 内容链接线**（TileAdmin/通道）：
- 通道 dispatch 后：bytes 到手（fetcher 同步读盘保持——文件 IO 快且已是队列
  交付语义）→ **Document 解析 submit 到 WorkerProxy** → 完成入队 → 主线程
  drain（TileAdmin::process 现有帧内点）→ readContent 后半（graphics）。
- `noWorker` env（DANQING_NO_WORKER=1）→ 全同步旧路径（降级面 1:1）。
- 取消语义：isCanceled 检查入 worker 完成路径（取消的瓦不建 graphics）。
- 锁：异步路径下既有 dump 像素锁全绿（回归即正确性）+ 完成帧序不变量
  （M-F(1) 的"交付不早于次帧选择趟"不变量在异步态保持——新增显式锁）。

**P-b4 打开链异步**（dqApp DumpOpenHelper）：
- manifest 解析 + 树 props 段 submit worker（复用 P-b1 载体；dqApp 消费
  dqRender 公开缝）；完成回主线程 → views/changeView 照旧。
- UI 面：卡片点击即时回显（状态栏 "Opening <model>…"）→ 完成后原
  "Opened <model> (N tile trees)" 确认（既有 showStatus 复用）。
- 打开链计时（DANQING_OPEN_TRACE 既有桩）增**主线程阻塞时长**字段——
  对拍基线：joeshouse Debug 2.87s→目标 UI 阻塞 <50ms 量级（解析下放后）。
- 锁：异步打开完成态与同步态终态对账（views/树数/请求面）+ UI 线程阻塞
  计时锁（宽上界）。

**P-b5 门禁**：
- Debug 全量 ctest（TD-26/29 规程）——异步为默认路径。
- noWorker 降级面抽测（env 翻转跑 dump 像素锁子集——两路径等价实证）。
- Release 抽验（五模型开链 + 计时对拍表）。
