## 2. 深层模式分析（为什么会反复发生）

### P1 节点移植 vs 链移植（最深）
`FrustumUniforms::changeFrustum` 是忠实移植——但**无人调用**：参考侧的喂入链
（`createRenderPlanFromViewport → RenderPlan.frustum → Target.changeRenderPlan:534`）没跟着移植，
于是上游自建了一条"看起来等价"的旁路。同理：doFit 丢 animate/aspect、滚轮合并层、导入动画。
**一个忠实的组件放在断裂的链上，平时不可见，直到角案（z 符号、纵横比、时序）引爆。**
这不是代码错误，是**移植完整性的度量单位错了**：以"类/函数"为单位完成，而参考的运作单位是**调用链**。

### P2 等价替换的隐性发散
worldToNdc 与 lookIn+ortho 在 xy 上逐像素一致、在 z 上符号相反。宣称等价时只检查了
"看得见的维度"。所有 P1 的自创旁路都自带此类发散（三个滚轮差异、animate/aspect）。
**等价性是全定义域命题，不是抽查命题。**

### P3 判据强度 < 缺陷隐蔽度
"中心像素有纹理"看不见面交换；"进程不崩"看不见黑帧；"像素非空"看不见双 bug 并存。
信息论地说：**断言的信息量必须 ≥ 失败模式的自由度**。面交换有一个自由度（哪个面），
断言就必须至少固定一个面朝向标记。本 session 之前所有贴图回归都只断言"有纹理"——
深度反转因此穿过全部回归落网到用户眼前。

### P4 仪器未校准的观测
BMP 行序、CWD 相对路径、视觉模型左右、陈旧 exe——共同点：**观测工具没有已知答案的自检**，
坏仪器产出的不是"无数据"而是"自信的错误数据"，会把取证引向不存在的病灶。
§12.9 教训 5 早已写下"取证工具先自测"，本 session 仍然重犯——说明**纪律条目不等于纪律执行**。

### P5 受控变量失控
同一物理量在两次测量之间被悄悄改变（资产内容、加载路径、页面状态、exe 版本），
对照实验退化成散文。用户的中途更正（"你用错了 gltf 文件""示例程序都不是最新编译的"）
三次都属于此类。

### P6 多根因叠加
"贴图左右反"先后由三个独立根因在不同时期各自成立（yAxisUp 缺失 → 天空画序 → 深度反转）。
修好一个症状仍在 = 还有下一个，但每次都倾向解读为"修复无效"而回滚或加补丁。

### P7 紧迫感驱动的流程降级
§12.8（用户等待压力下三层症状补丁）与本 session（快糙的资产突变代替规范的新建资产、
抢着 reload 用户的 DTA）同构。**时间压力是流程的溶剂。**

## 3. 防复发机制（模式 → 机制）

| 模式 | 机制 | 落点 |
|---|---|---|
| P1 链移植 | **链完整性表**：每子系统维护"参考调用链 → DanQing 对应调用链"映射；任务完成判据（§6 一致性表）增加一列"参考侧调用者 → DanQing 侧调用者"，**有ported无called的组件标红** | §6 流程扩展；新审计文档 |
| P2 隐性发散 | **等价替换登记制**：任何"DanQing 用相邻数据合成参考从别处取得的值"必须注释 `EQUIVALENCE: 参考源=<位置>, 已知发散=<清单>`，每条发散配一个能抓住它的测试（DEPTHLOCK 即此模式） | 代码注释规范 + 测试 |
| P3 弱判据 | **位置断言制度**：视觉特性回归至少一个 WHERE 断言（象限/朝向/标记侧），资产带不对称标记（BoxTexturedDots 先例） | 测试规范 |
| P4 坏仪器 | **仪器自检三则**：①新取证工具先用已知答案校准（合成图过同一写入器）②输出一律绝对路径③env 门控要验证真的生效；视觉模型的左右结论必须字节级复核 | §11.9 扩充 |
| P5 变量失控 | **A/B 协议**：同文件（打印哈希）、同视图 id、干净状态、测前重 dump 资产；用户配方是唯一 ground truth | 流程 |
| P6 多根因 | **修复后全扫**：每次修复后 8 标准视图 × 双 app 矩阵复扫 + 全部既有证据闭环，再宣布完成 | 流程 |
| P7 流程降级 | **检查前置于兴奋点**：改渲染管线前的"像素回归先行"、给用户验证前的"全量重建 + 证据复核"做成固定 checklist，不依赖记忆 | 流程 |

### 已经做对、必须保持的
- **先完整读参考再修**（§11.8）：凡遵守的（yAxisUp、天空画序、深度反转、滚轮合并），一次修中。
- **DTA cross-feed 对拍**：用 CDP 驱动参考实现提取字段级 ground truth（相机链、网格线距、天空基准色）。
- **env 门控探针族**（§13.1）：UV_DEBUG/MVP_TRACE 等——下一个 saga 从有仪器开始。
- **用户肉眼终验 + 精确配方**：唯一 ground truth，且每次配方纠偏都立刻改变结论。

## 4. 本 session 我方流程失误清单（诚实记录）
1. 探针资产原地多轮突变，导致早期测量不可复现——应每次新建资产文件。
2. CWD 相对路径读旧帧，两次假观测——工具未自检。
3. 视觉模型的左右结论未复核即采信——字节级验证应前置。
4. 未经确认 reload 了用户的 DTA（破坏其会话状态）——破坏性动作应先问。
5. CDP 合成状态（点击开视口）与用户真实流程不等价却用于下结论——采集通道失效后仍花了数轮。

## 5. 一句话总结
**参考是一个不变量系统，而我们曾以"功能"为单位移植；所有隐蔽缺陷都住在被跳过的链路、
被宣称的等价、和未被校准的仪器里。防复发的本质是把"链完整性、全定义域等价、
判据信息量、仪器自检"从纪律条目变成每次动手前的固定动作。**
